## 📋 更新概述

本次更新对 `templates/index.html` 进行了全面的前端解耦重构。原文件将 CSS（785行）、HTML 骨架（193行）、JavaScript（1963行）全部内联在单一文件中，维护困难。本次将 CSS 提取为独立样式文件，JavaScript 按功能域拆分为 16 个模块，统一放入 `templates/static/` 目录，并将 static 文件夹从项目根目录迁移至 `templates/` 下，同步更新 Flask 配置。

## 🔧 技术细节

### 全局变量管理

所有跨模块共享的变量统一在 `state.js` 中声明，包括：

- DOM 引用：`chatBox`、`userInput`、`sendBtn` 等
- 聊天状态：`currentMode`、`abortController`、`chatStreaming`、`hardwareRunning`
- 算法状态：`selectedAlgorithm`、`selectedFilePath`、`algorithmParams`
- 面板状态：`stepPanelTools`、`experimentSteps`、`panelZIndexCounter` 等

`state.js` 还包含共享工具函数 `collectToolParams(tool)`，消除了 `step_panel.js` 和 `experiment_design.js` 中完全相同的参数收集循环。

### JS 加载顺序

无 ES modules，所有函数为全局作用域，加载顺序决定依赖关系：

```
state.js → ui/panel.js → ui/menu.js → ui/input_state.js → notification.js
→ extraction/ → hardware/hardware.js → experiment/confirm → experiment/design
→ hardware/task_stream.js → hardware/step_panel.js
→ analysis/ → experiment/chat → chat/chat.js（最后）
```

完整说明见 [`templates/static/README.md`](../templates/static/README.md)。

### Bug 修复

重构过程中发现并修复了原代码中的两处 bug：

1. **算法面板 open 状态检查错误**（`algorithm_panel.js`）  
   原代码：`algorithm-panel.classList.contains('open')`  
   修复后：`app-wrapper.classList.contains('algorithm-mode')`  
   原因：算法面板通过 `algorithm-mode` class 控制显示，不使用 `open` class。

2. **流式响应结束后未恢复 UI 状态**（`chat.js`）  
   原代码：流式响应结束后只调用 `setChatStreamingState(false)`，缺少 `setNormalLoadingState(false)`  
   修复后：两者均调用，确保输入框正确恢复可用状态。
